# 统一评测机制实现与验证

日期：2026-10-05。范围：任务适配、配对执行与独立评价的衔接；没有新增模型试验。

## 完成的衔接

- 行为 case 与通过预检的 pytest／packaging 都转换为 [统一任务协议](../protocol.md)。Patch 的修复／遮蔽语义留在适配器，正式执行器不解释它。
- 真实任务使用独立 Codex 容器，只有公共工作区与 skill 组指导进入执行环境；评分材料和参考实现不挂载进去。
- 保存完整提交，包括新增文档、未跟踪文件及变化清单。评价复制提交后恢复可信测试，原始提交不改写。
- 预检与正式功能验收共用 `functional_checks.py` 的执行入口。独立 judge 读取功能证据进行工程／文档评审，不能覆盖功能失败。
- `--functional-only` 不调用 judge。功能通过但定性未评时，整体结论仍是 unknown；执行未完成时不把起始代码当作 Agent 的最终提交去判失败。

工程与交付要求对两组相同，适配说明写入 provenance；不强制文档数量或模板。现有历史运行及原始来源材料保留。
