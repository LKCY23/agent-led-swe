# D1 配对试跑：执行与独立评价链路

日期：2026-10-05。结论：本次基础链路跑通，两组均满足 D1；尚不能判断 skill 的整体开发收益。

## 任务与条件

D1 要求讨论 Tasks／Evaluation 的两个职责划分方案、取舍和待定问题，不确认方案、不写文档或代码。这是已有 development case，不是真实 SWE benchmark，也不覆盖完整开发过程。

两组使用 Codex CLI 0.160.0、`gpt-6.1-sol`、`high`，相同请求、起始文件与 `workspace-write` 权限，各一次、最多 180 秒。先 baseline，后显式使用 skill。两次独立 judge 使用相同模型和 effort，权限为 `read-only`，各最多 180 秒。四次调用全部完成，无重试。

## 隔离与证据核查

- 每次运行均创建新的临时工作区和 ephemeral 会话，不继承作者会话。
- 关闭插件、apps、memory、hooks、多 agent 与 skill search；通过本次命令的 `skills.config` 禁用发现的 51 个本地 skill。关闭自动注入的项目／用户开发指导；任务文件仍供 Agent 主动读取。没有修改全局配置或卸载 skill。
- 原先尝试的 `skip_host_skill_discovery` 开关没有清空目录，因此未采用它。逐项禁用后重新导出的初始上下文没有 skill 列表或目标内容；每次实际调用沿用检查后的覆盖项，executor 额外忽略用户配置。
- Baseline 的完整执行日志没有工具调用，因此没有通过文件读取接触目标 skill。Skill 组的八次命令均成功：六次读取目标指导，另两次列出和读取 fixture；没有读取评分材料或其他项目。
- 两次 judge 的命令均为评审目录内的读取和 diff；未修复产物。产物和轨迹可能暴露组别，因此是独立评审，不是盲评。

本次验证的是受控、减少预装指导的环境，不代表用户日常的完整插件环境。宿主仍允许读取工作区外文件，不能把发现检查当作文件系统隔离；今后的运行仍需检查轨迹。配置依据参见 [OpenAI 的 skill 禁用说明](https://learn.chatgpt.com/docs/build-skills#enable-or-disable-local-codex-skills)。
