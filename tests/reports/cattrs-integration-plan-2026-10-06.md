# cattrs 协作场景接入计划

依据：[已讨论的协作场景](cattrs-collaboration-scenario-2026-10-06.md)。基准为 `b7d308d`，在独立测试工作区分支 `feat/cattrs-collaboration-20261006` 实施；已接受 skill 不变。

## 本轮实施与验证

1. 冻结 cattrs 起始代码、上游需求和测试／参考补丁。建立只含依赖的镜像，任务源码运行时安装；公共工作区不含隐藏测试、参考答案或用户私有资料。
2. 在无网络的独立副本验证起始／参考实现：既有测试通过，起始实现缺少新能力，参考实现通过新增测试；同时检查原需求与测试是否冲突。未取得资格则暂停该题的真实试跑。
3. 接入双向交互所需机制：主动问答、轮末反馈、原生会话接续、用户只读检查、预算与错误处理、证据导出。按依赖顺序实现，并以模拟响应验证；不在执行器中安排固定开发阶段。
4. 功能 verifier 与后续流程分析保持独立。先检查正常交互及超时、服务错误、停止和隔离，再确定真实配对配置。

本轮真实模型预算为 0。环境构建与预检使用本地 Docker／uv；每次构建与检查有明确超时。真实调用需另行固定 solver／用户模型和有限预算。记录实际完成范围，不把模拟协议通过当作 skill 效果证据。

## 交付依据

- 任务和输入可追溯，资格记录与文件哈希绑定。
- verifier 不修改提交产物；保留原始功能判据，错误与断言失败可区分。
- 用户信息、验收材料和凭据不交给执行 Agent。
- 两组具备相同交互条件，skill 组原生安装调用；不会因切换轮次丢失决定或重复调用完整 skill。
- 文档说明已测试范围、尚未验证的宿主能力和真实试跑的剩余条件。
