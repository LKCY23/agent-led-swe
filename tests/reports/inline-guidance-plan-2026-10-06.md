# 指导直接提供诊断

## 问题与假设

此前两个 skill 执行没有读取配套指导，重要设计增量多在实现后记录。先检查直接提供这些指导是否改变行为，不同时改写规则或引入强制 hooks。

比较接受版本 `1c65c00` 与从该提交创建的诊断版本 `ee58579`。后者仅在 SKILL.md 末尾附上 Process、Design、Documentation and Traceability 三份原文；相对 Markdown 链接按原文件目录转换为入口可用路径。其他文件和入口原有规则保持不变。这是诊断材料，不是拟发布的最终结构。

## 执行与观察

- smolagents 已资格预检的同一冻结任务；开发样例。
- Claude Code 2.1.278，DeepSeek Flash/high；原版 → 诊断版，独立容器与会话。
- 每组一次、最多 1,800 秒，共 2 次执行；无自动重试、无 LLM judge。
- 使用相同任务、提示词、网络策略与 verifier；原始失败照常保留。
- 先用真实 CLI + 模拟 API 确认扩展后的全部入口正文进入首个模型请求，再启动真实模型。
- 观察必要指导是否被使用、重要约定是否先于相关实现记录、已有依据是否复用、结果是否在执行后记录、后续变化是否同步、交付是否核对原承诺。阅读动作和文件数量本身不代表成功。

同一份文档可以包含实施前约定和实施后结果。不要求统一目录、文件数量或对所有局部修改先写设计。

## 解释边界

直接提供也改变了输入长度、位置和重复程度；每组一次存在模型随机性。若行为改善，只支持优先排查指导获取与上下文组织；不证明唯一原因。若未改善，说明仅直接提供不足，不证明模型看到了每条规则却有意忽略。未经用户审阅不合并，不自动开展下一种候选。

测试工具仅增加 current／candidate 两组模式，保留默认 baseline 模式。此改动独立提交；不改变执行器、模型协议或功能判据。
