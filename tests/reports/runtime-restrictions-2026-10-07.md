# 运行限制清理

基准：`321963f`；修改仅在测试 worktree，正式 skill `1c65c00` 不变。

## 改动

| 原限制 | 修复 |
| --- | --- |
| 用户单轮 120／180 秒、整段对话 8／12 次回应 | 只保留每组 Solver＋用户共享的总时长；双方每轮使用剩余时间。 |
| 用户输出 4096 tokens、结构化输出只重试一次 | 去掉环境覆盖，交给原生 CC。 |
| Solver 只开放六种工具，禁止委派，屏蔽项目配置、hooks、Codex AGENTS.md | 恢复原生工具和项目指导；保留隔离 HOME 与网络边界。 |
| 强制给模型名追加 `[1m]` | 原样传入模型配置；历史日志仍兼容该后缀。 |
| worker 2 CPU／3 GB；网关 256 MB／64 进程／32 MB 请求／120 秒超时 | 去掉无任务依据的额外额度；宿主资源、原生客户端和服务商限制仍然存在。 |
| 用户当前轮没有成功 Read／Grep 就拒绝 accepted | 保留角色审阅要求与原始事件；审阅是否充分通过完整轨迹分析，不以一次工具调用替代判断。 |
| 用户资格必须匹配所有适配器哈希，否则禁止运行 | 历史预检可选附上；当前配置、实际工具和会话仍保存核查。 |
| 只有对话完成且原生调用通过才运行 verifier | 有可靠的冻结产物就独立验收；执行状态、用户接受和实验有效性分别保留。导出失败仍不能用旧副本验收。 |

此前已删除的用户内部 `--max-turns` 和隐藏搜索工具的 `--bare` 不再引入。

## 保留的边界

- 固定任务／版本／模型、显式总预算；两组相同条件，不自动追加模型试跑。
- 原生 skill 安装与调用检查、baseline 不暴露目标 skill。
- 私有 verifier／参考答案隔离，模型专用网络、独立容器／HOME、凭据仅交给网关。
- 模拟用户只读工具与快照；它审阅并回应，不承担开发或功能判分。
- 任务／verifier 预检、产物完整性、原生协议与模型一致性检查。
- 构建、安装、网络探测、verifier 各自的基础设施超时；它们不是 Agent 的开发轮数限制。

当前交互通过原生 headless 会话的文字回复与 resume 传递问题、反馈。恢复默认工具不等于已经接通原生交互式 UI 的所有回调；本轮不声称覆盖该能力。

## 验证

先冻结代码，再运行本地回归与真实 CLI＋模拟 API 检查。检查项目指导、原生工具发现、skill 安装调用、两轮接续、只读用户与独立验收；不调用真实模型，也不据此判断 skill 效果。结果在本节补充。
